这是一篇静态博客工程结构的演示笔记。项目还没有选择生成器，现阶段用原生 HTML、CSS 与 JavaScript 验证阅读体验，可以先把数据约定和样式边界整理清楚。

## 按职责放置文件 {#files}

```text
index.html                 首页索引
article.html               演示阅读入口
assets/js/data.js          文章元数据
assets/js/site.js          共用侧栏与入口
assets/js/article.js       正文增强
assets/css/article.css     正文排版
content/posts/*.html       独立正文片段
```

两个入口共用站点组件，不需要各自维护完整侧栏。正文则不携带导航和脚本，方便未来由模板或 Markdown 编译流程生成。

## 留下简单的数据约定 {#contract}

<ul><li>id 唯一并尽量保持稳定。</li><li>date 使用可排序的 ISO 日期。</li><li>content 指向本站的可信片段。</li><li>cover 可选，缺席时直接使用文字布局。</li></ul>

目录根据正文标题生成。重要章节可显式写 id，避免文字修改后长期链接跟着变化。图片路径相对于文章入口，并填写替代文本。

## 迁移时保留验证过的部分 {#migration}

生成器可以接管路由、模板和正文编译，而现有语义标签、CSS 令牌与原生组件交互继续使用。不必为了演示阶段就设计完整插件体系，也不必把页面渲染全部耦合到某一种工具。

下一步的选择应该由真实发布需求驱动。在此之前，把刷新、分享、无效链接和浏览器历史处理好，就是一个足够具体的边界。
