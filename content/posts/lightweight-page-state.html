这是一篇原生 JavaScript 状态组织的演示笔记。页面很小时，最重要的是知道状态从哪里来、由谁修改，以及刷新以后怎样恢复。

为每种信息选一个来源

文章元数据来自索引文件，正文来自独立片段，当前文章来自 URL，主题偏好来自本地存储。尽量不要再从已渲染的标题文本里反推业务数据。

  • 长期可分享的状态放进 URL。
  • 跨页面的偏好放进存储。
  • 输入过程和临时反馈保留在当前页面。

让 URL 参与页面状态

const url = new URL(location.href);
url.searchParams.set('q', 'CSS');
url.hash = 'recent';
history.replaceState(null, '', url);

搜索输入不必每敲一个字就增加一条历史记录。分类切换与文章跳转则应保留明确的返回路径。使用原生链接，还能自然支持新标签页、复制链接和浏览器返回。

组件状态交给组件

抽屉的 open 属性、原生 Tabs 的 value 和折叠目录的 value 都有现成的状态模型。业务代码只在需要时设置属性、响应事件，不再同时维护另一组开关类名。

从用户动作验证

  1. 打开带搜索参数的地址，确认列表一致。
  2. 切换分类，使用浏览器后退。
  3. 进入文章，刷新并复制当前地址。
  4. 切换主题，再打开另一篇文章。

当这些动作保持可预测时，状态流向通常也足够清楚。只有出现明确需求，再考虑额外的状态工具。
